# MSP Dashboard — Spec

## เป้าหมาย
Dashboard งบกำไรขาดทุนของ MSP จากไฟล์ Excel รายเดือน (`Data.xlsx`) รันบนเครื่อง local
พร้อมระบบสิทธิ์มาตรฐานที่พร้อมเชื่อมกับเว็บหลักในอนาคต

## Stack
- Next.js (App Router) + TypeScript, Tailwind CSS
- MySQL 8.4 (local, Windows Service), Drizzle ORM + mysql2
- Auth.js (Credentials ตอนนี้; OIDC/JWT จากเว็บหลักในอนาคต)
- exceljs (อ่าน Excel), กราฟเขียนด้วย HTML/CSS (เพิ่ม ECharts เมื่อมีกราฟแนวโน้มหลายเดือน)
- Vitest (ทดสอบ)

## รูปแบบไฟล์ที่นำเข้า
ไฟล์ Master ทั้งไฟล์ (เช่น `PreView_ForClaude/MSP-P_Lเชียงใหม่ 2026_08.xlsx`) แต่ระบบ **อ่านเฉพาะชีตงบที่แท็บสี `#002060`** ชีตอื่นไม่ใช้ (`src/backend/lib/master-import/parse.ts`)
- ชื่อชีต = เดือน: `ม.ค.` = งบรวมบริษัท, `<ภูมิภาค>_ม.ค.` (เช่น `เชียงใหม่_ม.ค.`, `น่าน_ม.ค.`) = ชีตภูมิภาค · ช่อง A1 ต้องเป็น `MASTER_`
- แถว 1 = รหัสหน่วย, แถว 2 = ชื่อหน่วย · หน่วยละ 3 คอลัมน์ (ยอดเงิน, %, ว่าง) เริ่มที่ C (C = ยอดรวมของชีต)
- คอลัมน์ A = Group, B = รายการ · อ่านถึงแถว "กำไร(ขาดทุน) ก่อนภาษี" (ส่วนปันส่วน HQ/ช่องทดเลขด้านล่างไม่อ่าน)
- **ดึงเฉพาะยอดราย Group ของหน่วยที่อยู่ในผังหน่วย** (กำหนดในโค้ดตามชีต `Preview_Code` — ดูหัวข้อผังหน่วย) แล้วระบบคำนวณยอดรวม/% เอง:
  - งบรวม: คอลัมน์ที่แถว 1 เป็นรหัสหน่วย (CM-HO, CM-CAR, FAC-*) · คอลัมน์ที่แถว 1 เป็นชื่อชีตภูมิภาค → อ่านจากชีตภูมิภาคนั้นแทน
  - ชีตภูมิภาค: ทุกคอลัมน์หน่วยยกเว้นคอลัมน์รวม (C) และคอลัมน์ที่ชื่อขึ้นต้นด้วย "รวม"
  - คอลัมน์หน่วยที่รหัสไม่อยู่ในผัง = **หน่วยงานใหม่ที่ตรวจพบ** → บันทึกใน `detected_units` (โซนเดาจากชีต) ยอดเก็บใน `group_amounts`
    แต่ยังไม่นับในงบจนกว่าผู้ดูแลเลือก Sales Zone / Operations ในแอปหลังบ้าน (หน้า หน่วยงานใหม่) → หน่วยเข้าผังใต้ Sz-/Op- ของโซน แล้วคำนวณงบใหม่ทันที
  - หน่วยในผังที่ไม่พบในไฟล์ → แจ้งในหน้าตรวจไฟล์
- ตรวจ: ยอดรายได้รวม/กำไรขั้นต้น/กำไรจากการดำเนินงาน/กำไรก่อนภาษีที่คำนวณจากทุกคอลัมน์หน่วยในชีตต้องตรงกับคอลัมน์ C ของทุกชีต ไม่ตรง → แจ้งในหน้าตรวจไฟล์
- ใช้ผลสูตรที่ Excel บันทึกไว้ (ไฟล์ต้องบันทึกจาก Excel หลังคำนวณ) · เดือนที่ยอดเป็น 0 ทั้งหมดถูกข้าม · ปีให้ผู้อัปโหลดระบุ (พ.ศ.)
- สำเนาโค้ดรูปแบบเดิม: `backup/import-format-v1/` (ชีตงบจากสีแท็บ เก็บยอดตามไฟล์) และ `backup/import-format-v2/` (ชีต `MASTER_<เดือน>`) — ไม่อยู่ใน git

### การคำนวณ (Backend — `src/backend/lib/master-import/compute.ts`)
ทำแบบเดียวกับชีตงบใน Excel (`SUMIFS` ตาม Group + สาขา แล้วรวมตาม Flow ใน `PreView_ForClaude/รายได้.txt`):
1. ยอดต่อ Group ของแต่ละสาขา = ผลรวมยอดในไฟล์ · **XW, XY ติดลบเสมอ** (`−|ยอด|`) เพราะหักล้างกับ XQ/XX ที่ HO โอนให้สาขา
   (ไฟล์ Excel บางเดือนบันทึกบวกแล้วสูตร ×−1 บางเดือนบันทึกลบมาแล้ว)
2. หน่วยแม่ = ผลรวม Group ของตัวเองและลูกหลานตามผังหน่วยในระบบ (เท่ากับคอลัมน์รวมของ Excel เพราะ Flow เป็นการบวกลบล้วน)
3. รายได้รวม = A+B+C+M · สินค้ามีไว้เพื่อขาย = AA+D+E+F+G+XX+XZ+XQ+XW+XY+FF+H+I · รวมต้นทุนขาย = −AB
   · รวมต้นทุนอื่น = BA+J+K+KK+L−BB · COGS = สองยอดรวม · GP = รายได้รวม − COGS
   · OP = GP − (N..Q) − (R..Z) · PBT = OP − (ZZ+ZZZ) · % = ยอด ÷ รายได้รวมของหน่วย × 100
4. เก็บยอดต่อ Group ใน `group_amounts` และงบที่คำนวณแล้วของทุกหน่วยใน `statement_lines` — หน้าเว็บอ่านผลสำเร็จอย่างเดียว
5. **Group ใหม่** (รหัสคอลัมน์ A ที่ไม่อยู่ใน Flow ข้างบน): ยอดเก็บใน `group_amounts` แต่ยังไม่นับ · บันทึกใน `detected_groups` ให้ผู้ดูแลเลือกหมวด
   ในแอปหลังบ้าน (เมนู Group ใหม่): รายได้ / ต้นทุนขาย / ต้นทุนขายอื่นๆ / ค่าใช้จ่ายขาย / ค่าใช้จ่ายบริหาร / ใต้กำไรจากการดำเนินงาน
   → ยอดบวกเข้ายอดรวมของหมวด (ใต้ OP = หักจาก OP) มีแถวของตัวเองท้ายหมวด และงบคำนวณใหม่ทันทีโดยไม่ต้องนำเข้าไฟล์ซ้ำ

ตรวจกับไฟล์ตัวอย่างแล้ว: ทุกชีตงบ ม.ค. ตรงกับที่ Excel คำนวณ (`src/backend/lib/master-import/sample-file.test.ts`)

### ผังหน่วย (กำหนดในโค้ด — `src/backend/lib/master-import/units.ts`)
ตามชีต `Preview_Code` ของไฟล์ Master (ชื่อหน่วยตามชีตนี้):
MSP Interfood (รหัส `MSP`) → Zone → Operations (Op) / Sales Zone (Sz) → หน่วย
- `Zone-CMI` → `Op-CMI`: CM-HO, CM-CAR, FAC-PIG, FAC-PIG1, FAC-PIG2, FAC-CHICKEN, FAC-FISH, FAC-VEG · `Sz-CMI`: CM-101…CM-167 (58 สาขา)
- `Zone-NAN` → `Op-NAN`: NAN-HO · `Sz-NAN`: NAN-402…411
- `Zone-SU` → `Op-SU`: SU-HO · `Sz-SU`: SU-501…514
- หน่วยใต้ Op = `category operations` (หน้า Operations) · ใต้ Sz = `category sales` (หน้า Sales Zone แสดง Sz-* เป็นโซน)
- รหัสกลุ่ม Op-*/Sz-* ตั้งในโค้ด (ชีตไม่มีรหัส และรหัสต้องไม่ซ้ำกันทั้งผัง)
- ตาราง `units` ถูกแทนด้วยผังนี้ทั้งหมดทุกครั้งที่นำเข้าไฟล์ และตอน `npm run db:seed` (หน่วยที่ไม่อยู่ในผังถูกลบ)
- สิทธิ์ผู้ใช้ของหน่วยผังเดิม: CMI-SHOP → Sz-CMI, NAN → Zone-NAN, SU → Zone-SU (เห็นข้อมูลชุดเดิม) · หน่วยเดิมอื่นที่ถูกลบ สิทธิ์ถูกลบ
- ผังที่ใช้จริง = ผังในโค้ด + หน่วยงานใหม่ที่ผู้ดูแลเลือกประเภทแล้ว (`buildUnitTree`)
- **หลายหน่วยงาน:** MSP (รวมทุกหน่วยงาน) → หน่วยงาน (`ORG-<รหัส>`) → Zone → Op/Sz → หน่วย · หน่วยงานเริ่มต้น MSP Interfood (รหัส MSPI, กลุ่มใช้รหัสเดิม Zone-CMI/Sz-CMI)
  หน่วยงานอื่นเพิ่มในแอปหลังบ้าน (ตาราง `organizations`, รหัส O2, O3, …) กลุ่มของหน่วยงานอื่นมีรหัสนำหน้า (`O2-Zone-CMI`, `O2-Sz-CMI`) และสร้างเฉพาะโซน/กลุ่มที่มีหน่วย
- แอปหลังบ้าน: หน้า **หน่วยงาน Sales Zone** / **หน่วยงาน Operations** — ปุ่ม **แก้ไข** (ข้าง Export) เปิดช่องติ๊ก แล้ว "แก้ไขที่เลือก" เปลี่ยน โซน/หน่วยงาน/ประเภท หลายหน่วยพร้อมกัน (เพิ่มหน่วยงานใหม่ได้)
  คลิกแถวนอกโหมดแก้ไข = แก้ทีละหน่วย (รวมชื่อ) · หน้า **หน่วยงานใหม่** (เลือกประเภท/โซน/หน่วยงาน/ชื่อ)
  การแก้หลายหน่วยส่งเป็นคำขอเดียว (`/api/admin/leaf-units/bulk`, `/api/admin/pending-units/bulk`) แทนผังและคำนวณงบครั้งเดียว
  - หน่วยในโค้ด: ค่าที่แก้เก็บใน `unit_overrides` (เฉพาะค่าที่ต่างจากโค้ด) ใช้ทับทุกครั้งที่แทนผัง · คืนค่าตามโค้ดได้ในหน้าแก้ไข
  - หน่วยใหม่จากไฟล์: แก้ที่ `detected_units` · บันทึกแล้วแทนผังและคำนวณ `statement_lines` ใหม่ทันที
- แก้ผังในโค้ดที่ `units.ts` แล้วรัน `npm run db:seed` หรือนำเข้าไฟล์ใหม่

สำเนาผังเดิม (แก้ในแอปหลังบ้านได้ + วางหน่วยใหม่ตามชีต) เก็บไว้ในเครื่องที่ `backup/unit-tree-before-code/` (ไม่อยู่ใน git)

## ข้อมูล
- `units(code, name, parent_code, level, sort_order)` — บริษัท(MSP) → หน่วยธุรกิจ → สาขา
- `accounts(code, name, section, sort_order)` — ใช้จัดหมวดค่าใช้จ่ายเท่านั้น
- `statement_lines(period, unit_code, line_no, kind, group_code, total_key, label, indent, amount, pct)` — ทุกแถวของทุกหน่วยตามไฟล์
- **ข้อมูลหลักแยกตามปี:** `units`, `unit_closure`, `zones`, `unit_categories`, `organizations`, `detected_units`, `unit_overrides`, `detected_groups`, `group_names`, `branch_areas` มีคอลัมน์ `year` (ค.ศ.) ใน primary key
  งบของงวดคำนวณด้วยข้อมูลหลักของปีงวดนั้น · ปีใหม่ (นำเข้าไฟล์ปีนั้นครั้งแรก) เริ่มจากสำเนาของปีก่อนหน้า (`ensureYear`) ถ้าไฟล์มีชีต Branch_Area ใช้ ตร.ม. จากไฟล์
  แอปหลังบ้านแนบ `?year=` ทุกคำขอ (`requestYear` ใน `admin-api.ts`) · Dashboard จัดหน่วยตามผังของปีเดือนล่าสุดที่เลือก (`treeYearOf`) · สิทธิ์ผู้ใช้ผูกกับรหัสหน่วยร่วมกันทุกปี
  ย้ายฐานข้อมูลเดิม: `scripts/migrate-master-years.ts` (npm start รันให้ก่อน drizzle-kit push)
- **ไฟล์ Master ปีละไฟล์:** นำเข้าไฟล์ของปีหนึ่ง = ลบยอดของปีนั้นทั้งปี (`group_amounts`, `total_overrides`) แล้วใส่ของไฟล์ใหม่ใน transaction เดียว ปีอื่นคงเดิม · งบ (`statement_lines`) คำนวณใหม่ทุกปีจากผังหน่วยปัจจุบัน
- `upload_logs` = ประวัติไฟล์ Master สถานะ `active` (ใช้อยู่ปีละ 1 ไฟล์ — ปีดูจาก `period`) → `backup_pending` → `backed_up` · ไฟล์ที่ถูกแทนคือไฟล์ปีเดียวกันเท่านั้น
  ไฟล์เก็บที่ `storage/masters` จนกว่าจะย้ายขึ้น Google Drive สำเร็จ (`src/backend/lib/master-backup.ts`, `src/backend/lib/google-drive.ts`)
  backup ล้มเหลวไม่ขวางการนำเข้า กดส่งใหม่ได้จากหน้าประวัติ
- การคำนวณที่เหลืออยู่มีเฉพาะการวิเคราะห์ข้ามงวด/ข้ามหน่วย เช่น YTD, อัตราส่วน, เทียบงวด
- `facts` เป็นตารางรูปแบบเดิม ไม่ได้ใช้แล้ว

## สิทธิ์
- RBAC: `users`, `roles`, `permissions`, `role_permissions`, `user_roles`
- Data scope: `user_unit_scopes` + `unit_closure` (สืบทอดลงลำดับชั้น)
- ทุก query ข้อมูลการเงินอยู่ใน `src/backend/lib/reports.ts` และกรองด้วย `user.allowedUnits` (คำนวณใน `src/backend/lib/session.ts`)
- Roles เริ่มต้น: admin, executive, accountant, branch_manager
- Permissions: `dashboard.view`, `report.export`, `data.upload`, `users.manage`
- `users.auth_provider`, `users.external_id` เตรียมไว้สำหรับ SSO
- `upload_logs` บันทึกการอัปโหลด

## หน้าจอ v1
1. Login
2. Dashboard: ตัวเลขหลัก (รายได้รวม, กำไรขั้นต้น/%, กำไรก่อนภาษี), แถบ "จากรายได้ทุก 100 บาท", อันดับหน่วย, drill-down เข้าสาขา, ตารางงบกำไรขาดทุน
3. อัปโหลด Excel (ต้องมี `data.upload`) — ตรวจไฟล์ (ยอดรวมรายเดือนที่คำนวณได้ + ยอดไม่ตรงกับไฟล์ + หน่วยใหม่ + คำเตือน) ก่อนยืนยัน
   - ไฟล์ที่ตรวจแล้วค้างไว้ที่เซิร์ฟเวอร์ แยกตามผู้ใช้ (`storage/drafts/<userId>`, `src/backend/lib/upload-draft.ts`) — เปลี่ยนหน้า/รีเฟรช/ปิดเบราว์เซอร์แล้วกลับมา ไฟล์และสรุปยังอยู่
     หายเมื่อนำเข้าสำเร็จ กดยกเลิก หรือเลือกไฟล์ใหม่ · ปี พ.ศ. ที่แก้ไว้ถูกจำด้วย
4. จัดการผู้ใช้ (ต้องมี `users.manage`)
